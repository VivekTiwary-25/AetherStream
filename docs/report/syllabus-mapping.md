# CDD syllabus evidence mapping

Links below point to files in this checkout or to the repository's GitHub Actions workflow pages. Workflow definitions establish configured checks, not that a run passed; inspect the linked Actions page for the branch and commit being assessed. `not covered` means this checkout has no evidence for the stated skill or outcome.

| Syllabus area | Concrete repository evidence and limits |
|---|---|
| Version control and collaboration | [Project report §7](project-report.md#7-team-and-process) documents lane ownership, `task/**` branches, review, and merge to `main`; [CI Java](../../.github/workflows/ci-java.yml) ([Actions](https://github.com/VivekTiwary-25/AetherStream/actions/workflows/ci-java.yml)) and other workflows run on task branches. Actual clone/fetch/pull/push practice, team contribution history, and verified collaboration records: **not covered** here. |
| Branching, merging, and code review | Task-branch CI and PR-to-main triggers are configured in [ci-java](../../.github/workflows/ci-java.yml) ([Actions](https://github.com/VivekTiwary-25/AetherStream/actions/workflows/ci-java.yml)) and [ci-web](../../.github/workflows/ci-web.yml) ([Actions](https://github.com/VivekTiwary-25/AetherStream/actions/workflows/ci-web.yml)); the process is described in [project report §7](project-report.md#7-team-and-process). A reviewed PR, merge/conflict-resolution demonstration, or branch-protection evidence: **not covered** by these definitions. |
| Continuous integration | [CI/CD evidence inventory and dated run snapshot](ci-cd-evidence.md#workflows) links all 12 workflows and their Actions pages. For this task, the required check is [ci-mock](../../.github/workflows/ci-mock.yml) ([Actions](https://github.com/VivekTiwary-25/AetherStream/actions/workflows/ci-mock.yml)); its smoke test exercises the dev mock server only. Check the task-branch run rather than inferring success from YAML. |
| Continuous delivery | [cd.yml](../../.github/workflows/cd.yml) ([Actions](https://github.com/VivekTiwary-25/AetherStream/actions/workflows/cd.yml)) publishes four SHA-tagged GHCR images only on pushes to `main`; deploy also requires `refs/heads/main` and runs on `[self-hosted, aether-deploy]`. Manual dispatch can select a SHA but does not publish. [Deployment evidence guide](devops-evidence.md#6-self-hosted-runner-evidence) and [project report §6](project-report.md#6-devops-and-delivery) document proof limits. A green task-branch run is not a deployment. |
| Docker images and containers | Custom images: [engine](../../infra/docker/engine.Dockerfile), [simulator](../../infra/docker/simulator.Dockerfile), [control API](../../infra/docker/control-api.Dockerfile), and [web](../../infra/docker/web.Dockerfile); services are assembled in [docker-compose.yml](../../docker-compose.yml). [ci-images](../../.github/workflows/ci-images.yml) ([Actions](https://github.com/VivekTiwary-25/AetherStream/actions/workflows/ci-images.yml)) builds and smoke-checks images with `push: false`; [ci-compose](../../.github/workflows/ci-compose.yml) ([Actions](https://github.com/VivekTiwary-25/AetherStream/actions/workflows/ci-compose.yml)) builds, starts, smokes, and tears down the stack. |
| Orchestration: Compose and kind/Kubernetes | Compose stack and smoke: [docker-compose.yml](../../docker-compose.yml), [smoke script](../../infra/scripts/smoke.sh), and [ci-compose](../../.github/workflows/ci-compose.yml) ([Actions](https://github.com/VivekTiwary-25/AetherStream/actions/workflows/ci-compose.yml)). Kubernetes manifests and deployment limits: [infra/kubernetes/](../../infra/kubernetes/) and its [README](../../infra/kubernetes/README.md); [ci-k8s](../../.github/workflows/ci-k8s.yml) ([Actions](https://github.com/VivekTiwary-25/AetherStream/actions/workflows/ci-k8s.yml)) validates manifests, deploys to kind, and checks recovery. The guide describes a single-node development baseline, not HA production. |
| Infrastructure as code: Terraform | [infra/terraform/](../../infra/terraform/) and [README](../../infra/terraform/README.md) document a local Docker-provider environment. [ci-terraform](../../.github/workflows/ci-terraform.yml) ([Actions](https://github.com/VivekTiwary-25/AetherStream/actions/workflows/ci-terraform.yml)) formats, validates, applies real Docker resources, checks readiness, and destroys them. This is not cloud provisioning; a successful current run must be checked in Actions. |
| Monitoring: Prometheus and Grafana | [Monitoring README](../../infra/monitoring/README.md), [Prometheus configuration](../../infra/monitoring/prometheus.yml), and [Grafana dashboard](../../infra/monitoring/grafana/dashboards/aetherstream.json) document optional Compose monitoring, scrapes, and dashboard panels. Metrics may be absent until instrumentation is exposed; this configuration alone does not establish live telemetry or performance results. |
| Testing: unit, integration, end-to-end, UI, soak, property | [Testing guide](../testing.md) maps test suites and limitations. Unit: [ci-java](../../.github/workflows/ci-java.yml) ([Actions](https://github.com/VivekTiwary-25/AetherStream/actions/workflows/ci-java.yml)); Testcontainers integration: [ci-integration](../../.github/workflows/ci-integration.yml) ([Actions](https://github.com/VivekTiwary-25/AetherStream/actions/workflows/ci-integration.yml)); full-stack Compose demo: [ci-e2e](../../.github/workflows/ci-e2e.yml) ([Actions](https://github.com/VivekTiwary-25/AetherStream/actions/workflows/ci-e2e.yml)); browser test: [ci-ui-e2e](../../.github/workflows/ci-ui-e2e.yml) ([Actions](https://github.com/VivekTiwary-25/AetherStream/actions/workflows/ci-ui-e2e.yml)) runs a six-step Playwright demo. The browser workflow's comment calls it advisory while UI surfaces are being integrated; confirm its run result. Soak and property-based testing: **not covered**. The [bench workflow](../../.github/workflows/bench.yml) ([Actions](https://github.com/VivekTiwary-25/AetherStream/actions/workflows/bench.yml)) runs a benchmark test, not a documented soak or property suite. |
| UX, design thinking, prototyping | [DEMO.md](../../DEMO.md) gives a presenter script and explicitly distinguishes mounted UI from absent controls; [UX overview](../ux/README.md), [design thinking](../ux/design-thinking.md), [personas](../ux/personas.md), [journeys](../ux/journeys.md), [usability decisions](../ux/usability-decisions.md), [design system](../ux/design-system.md), and [Figma plan](../ux/figma-plan.md) provide rationale, artifacts, and proposals. Screenshots in [docs/ux/screenshots/](../ux/screenshots/) cover selected deployed views. Personas and journeys are assumptions; no completed Figma prototype, participant study, SUS result, or accessibility conformance result is claimed. |
| Agile and project management | [Project report §7](project-report.md#7-team-and-process) describes lane ownership, task branches, review, and CI-before-merge. It is process documentation, not evidence of sprint ceremonies, backlog/iteration history, verified team roles, or completed reviews; those outcomes are **not covered** by the cited files. |
| Security basics | Org scoping is tested by [OrgAccessIT](../../tests/src/test/java/io/aetherstream/tests/OrgAccessIT.java); [architecture §2](../architecture.md#2-control-plane-data-plane-and-recovery-coordination) states `X-Org` is an organization selector, not authentication or an admin role. [CD workflow](../../.github/workflows/cd.yml) ([Actions](https://github.com/VivekTiwary-25/AetherStream/actions/workflows/cd.yml)) restricts publish/deploy to `main` and deploys only on `[self-hosted, aether-deploy]`; this does not prove runner hardening or secret safety. [Kubernetes README](../../infra/kubernetes/README.md) warns example credentials are public. Authentication, authorization roles, production secrets controls, and a security audit: **not covered**. |
