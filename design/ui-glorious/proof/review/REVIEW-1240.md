## 1. CONFIRMED, FIXED: full unit suite red after the Ask AI 429 change
- `web/src/glorious/pipelines/__tests__/pipelines.test.tsx:128` still expected the AI 429 message to match `/busy/`. ea94b79c (merged in 6c194101) changed `describeError` (`pipelines/api.ts:59`) to "The AI is still finishing the previous request. …", which does not contain "busy".
- Impact: no effect on the running demo, but `npm test` / check-all `web-test` fails, so any pre-merge gate is red and real regressions get hidden behind it.
- Fix: the assertion now checks the exact new message. The new message itself is fine (see 4).

## 2. CONFIRMED, FIXED: a failed idle prefetch broke Live World until reload
- `web/src/glorious/prefetch.ts:3` (`pending ??= importer()`) cached the promise even when it rejected. `LiveWorld = lazy(prefetchLiveWorld)` (`GloriousApp.tsx:13`) reuses that same promise, so a single network or chunk blip during the idle prefetch on Home (for example on the kiosk Wi-Fi, or while the web container restarts during a refresh) made the later **Live World click** reject without ever trying again.
- There is no error boundary anywhere in `web/src` (see 3), so that rejection unmounts the whole app: a blank screen in the middle of the demo. Before the prefetch, the import ran at click time and only a failure at that exact moment could do this. The comment "Keep speculative failures out of the UI" at `GloriousApp.tsx:31` was not true.
- Fix: on rejection, `pending` is cleared and the error is re-thrown, so the next call imports again. Successful loads are still shared (the existing test still passes). New test "retries the import after a failed prefetch…" fails without the fix and passes with it.
- The rest of the prefetch is correct. It runs only on Home, skips `saveData`, uses requestIdleCallback or a 1 s timeout as fallback and cancels it on unmount or screen change, and the `.catch` stops unhandled rejections. navigation.test.tsx stubs are cleaned up by `vi.unstubAllGlobals()` in `afterEach`.

## 3. Pre-existing, not fixed (too big for this task): no error boundary around the lazy screens
