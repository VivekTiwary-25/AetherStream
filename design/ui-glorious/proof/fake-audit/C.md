# C — Pipelines: honest failure states

## Visible values: item -> source -> status

- PipelinesPanel prompt text -> user input or the explicitly named `examples.ts` prompt chips -> OK. These are editable pipeline definitions, never telemetry.
- Generated pipeline name, nodes, parameters and connections -> `POST /api/glorious/ai/generate`, checked by `isPipeline`; `PipelineReview` uses `describePipeline`/`describeNode` -> OK. No client-side generation or synthetic result fallback.
- AI attribution, model and generation duration -> response `source`, `model`, `ms`; the bridge measures elapsed monotonic time and reports its configured model -> OK. These describe generation, not stream health.
- Saved-example fallback -> bridge `generate()` catches AI errors, including its CLI timeout, and returns `source: example`; PipelinesPanel displays “Saved example” and never “Generated by AI” -> OK. The template must still pass the real run endpoint.
- Thinking elapsed seconds -> local `Date.now()` since the request started -> OK. Unsupported “Usually 10–30 seconds” estimate -> FIXED: removed; bridge CLI timeout alone is 60 seconds and generation can retry.
- AI outage/HTTP timeout -> rejected fetch or unsuccessful `/ai/generate` response -> OK. Tests cover network failure, 408, 504 and other HTTP errors; no review, Run control or results appear on failure.
- PipelineReview source label -> implicit truck-position source in the shared pipeline contract and `PipelineRuns.consume()` -> OK. This labels configured input, not a claim that Kafka is currently connected.
- Review step order, types, descriptions, branch labels -> returned pipeline nodes/edges via `orderNodes` and `describePipeline` -> OK. No displayed results are inferred from a definition.
- Editor pipeline name, node IDs, canvas positions, parameters and edges -> this tab’s sessionStorage draft, localStorage handoff, explicit Load example, or direct user edits; `pipelineToFlow`/`flowToPipeline` -> OK. Empty editor starts with no steps.
- Editor handoff attribution -> stored pipeline definition, which does not retain AI/example provenance -> FIXED: neutral “handed over from Pipelines,” not a claim that a saved example came from AI.
- Editor example names and loaded values -> explicitly selected `EXAMPLES` definitions -> OK. Load feedback identifies them as examples; they do not populate ResultsView.
- Step palette, comparison operators, group-by options, 12-step limit and new-node defaults -> `NODE_KINDS`, `DISPLAY_NAMES`, `OPS`, `STRING_OPS`, `GROUP_BY`, `MAX_NODES`, `defaultParams` in the shared model -> OK. Configuration choices/defaults, not observed telemetry.
- StepInspector field names/types -> `GET /api/glorious/pipelines/fields`; `GloriousPipelineController.fields()` returns contract metadata -> OK. Inspector values, candidate inputs and output/alert names come from the selected editable node and graph.
- Contract-field fallback -> `CONTRACT_FIELDS`, matching the controller’s nine field names/types -> FIXED: loading and empty/unusable API metadata now explicitly disclose contract fields; network failures already disclosed the fallback. This is schema, not sample truck data.
- Validation success and errors -> `POST /api/glorious/pipelines/validate`; node IDs/messages also arrive with HTTP 400 -> FIXED: HTTP 400 validation errors now feed node badges/error lists as well as page feedback. Edits discard outdated validation responses.
- Run-start outcome -> `POST /api/glorious/pipelines/runs`, then returned `runId` opens a keyed ResultsView -> OK. Rejected starts display errors and open no fabricated results window.
- Busy-service attribution -> HTTP 429 in `describeError` -> FIXED: pipeline errors no longer claim the AI is busy.
- Results polling cursor -> `GET /api/glorious/pipelines/runs/:id/results?after=...`; controller requires a non-negative cursor and `PipelineRuns.emit()` starts sequences at 1 -> FIXED: initial cursor is 0, not the rejected -1. Tests now match the real sequence contract.
- Running/Stopped/Failed, Events in and failure detail -> results response `state`, `eventsIn`, `error` -> OK. Client does not mark a run stopped just because Stop was clicked.
- Buffered result count -> retained API rows, capped at 500; newest 100 rows are displayed -> FIXED: count is explicitly labelled “Buffered results,” and remains unknown (`-`) before the first successful page rather than asserting zero.
- Result time, kind, output, dynamic columns and cells -> API `results[].ts/kind/output/data`; formatting only in `formatTime`, `resultColumns`, `formatCell` -> OK. Server emissions originate from the evaluator consuming Kafka truck-position records; no example rows are inserted.
- Results polling failures -> rejected request -> OK for “Disconnected,” error details, retained previously received rows and retry backoff. Empty-result outage text -> FIXED: “Results unavailable. Waiting to reconnect,” not a claim that an inaccessible run has no matches.
- Stop status/error -> `POST /api/glorious/pipelines/runs/:id/stop`, with terminal state confirmed by results polling -> OK. Stop failure remains an error, not fabricated STOPPED state; terminal pages stop polling.
- Editor/hidden modes -> `mode.ts` constant (currently `full`), with existing mode tests covering panel controls, editor links, sidebar and guarded direct/history navigation -> OK. Editor mode hides AI controls; hidden mode renders no pipeline panel.

## Verification and limits

- Browser smoke on an isolated local Vite server at port 5179, with no API responses intercepted: editor displayed the contract-field fallback, Validate displayed the real proxy HTTP 500, and Generate displayed “AI service unavailable” with zero review/results elements. Both editor and AI-failure surfaces were visually inspected.
- The first requested Vitest run exposed this workstation’s Node 26/Vitest Web Storage collision: `window.localStorage` was undefined. Standalone JSDOM storage was available. The test command is run with `NODE_OPTIONS=--no-experimental-webstorage` so JSDOM supplies its own storage; no production storage behavior is mocked or changed.
- Live successful AI/Kafka execution -> external services were not started or altered -> QUESTION. Failure rendering is browser-observed; service responses and terminal states are exercised in isolated Vitest tests, not claimed as live-service proof.
- Requested worker report under `swarm/reports/` -> repository agent rules prohibit writing under `swarm/` -> QUESTION. This audit is the allowed report artifact; no commit or branch change was made.
