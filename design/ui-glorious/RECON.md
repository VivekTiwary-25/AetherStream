## a) Kill worker: request, process exit, restart

- The old UI opens confirmation and fetches workers; busiest preview sorts by partition count. Confirm submits `null` for busiest or the selected worker ID. Sources: `web/src/app/chaos/ChaosPanel.tsx:24,61-80`.
- `killWorker(workerId)` sends `POST /api/chaos/kill-worker`, JSON `{"workerId":null}` or `{"workerId":"worker-1"}`; response is `{"workerId":"worker-1"}`. Source: `web/src/app/chaos/chaosApi.ts:9-11,100-106`.
- The API requires an owned current RUNNING/RECOVERING execution, then forwards the body to `POST /coord/chaos/kill`. Sources: `control-api/src/main/java/io/aetherstream/api/ControlApiController.java:125-141`; `control-api/src/main/java/io/aetherstream/api/UpstreamClients.java:49-57`.
- Coordinator resolves null/blank to the live worker with most partitions, or validates the explicit live ID; it queues `Command.Kill`, audits, and returns the ID. It does not mark the worker dead immediately. Sources: `engine/src/main/java/io/aetherstream/engine/coordinator/CoordinatorHttpServer.java:131-135`; `engine/src/main/java/io/aetherstream/engine/coordinator/Coordinator.java:572-600`.
- Wire command is `{"type":"KILL"}` inside heartbeat response `commands`, not a Docker command. Sources: `common/src/main/java/io/aetherstream/common/protocol/Command.java:9-27`; `engine/src/main/java/io/aetherstream/engine/coordinator/Coordinator.java:273-308`.
- Worker polls coordinator roughly every 1,000 ms, processes KILL, and invokes `Runtime.getRuntime().halt(137)`: abrupt JVM termination, no shutdown hooks. No `docker kill`, `docker stop`, or external process signal is issued. Sources: `engine/src/main/java/io/aetherstream/engine/worker/WorkerMain.java:43-71`; `engine/src/main/java/io/aetherstream/engine/worker/Worker.java:77-86`.
- Addressed IDs/services are `worker-1`, `worker-2`, `worker-3`, configured by `WORKER_ID`; no hardcoded Docker container names or `container_name` declarations. Sources: `docker-compose.yml:29-45,196-215`.
- All workers inherit `restart: unless-stopped`; Docker restarts the exited worker with the same configured ID. A manually stopped container is different. Source: `docker-compose.yml:29-45,196-215`.
- Missing heartbeats declare DEAD after 4,000 ms, but same-ID registration can instead trigger recovery immediately because its previous state was lost. Sources: `engine/src/main/java/io/aetherstream/engine/coordinator/Coordinator.java:41-44,244-270,732-781`.
