# t261119-0053-170a — T06 coordinator

Built the coordinator in `engine/.../coordinator/`: `Coordinator` (one lock, 250 ms `tick()`: heartbeat timeout 4 s, checkpoint trigger/30 s timeout, round-robin assignment, generation bump + CANCEL/ASSIGN recovery from the latest COMPLETED manifest, audit rows, chaos KILL/SET_SINK_DELAY, restart recovery after one heartbeat timeout), `CoordinatorHttpServer` (all contract 03 §2 endpoints), `CoordinatorMain`, `ExecutionRepository` (Postgres and in-memory), `KafkaOffsetsLookup`, and `Clock`. It also adds `storage/` (`CheckpointStore`, `S3CheckpointStore` with MinIO that creates the bucket if missing, `InMemoryCheckpointStore`), `db/DataSources` (Hikari from PG_* env) and `logback.xml`.
There are 11 unit tests (fake clock, in-memory deps): partition split + checkpoint 0 offsets in ASSIGN; partial acks do not complete; manifest is written before COMPLETED (the order is checked); stale acks are rejected; worker death → RECOVERING / generation 2 / pending ABORTED / CANCEL+ASSIGN from cp1 → RUNNING with restoredFromCheckpoint=1; incomplete checkpoints are never used; no-worker start; coordinator restart; chaos; stop; plus an HTTP smoke test using HttpClient.
Checked locally: `./gradlew :engine:build` passes with all 11 tests green. The machine only has JDK 25, so I used a temporary init script outside the repo that compiles with `--release 21`. CI on JDK 21 has not been seen yet.
Choices and notes: the first assignment uses generation 1 without a bump (the task says so, while contract 03 §3 says every assignment bumps first). ASSIGN `startOffsets` holds only that worker's partitions. Workers registering after an assignment get no partitions until the next recovery, because there is no live rebalancing. I added an optional `COORDINATOR_PORT` env (default 8081) and `GET /coord/executions/{id}`.
Left undone: the Postgres repository and S3 store are untested against real services (that needs the integration-test task). No build changes were needed.
