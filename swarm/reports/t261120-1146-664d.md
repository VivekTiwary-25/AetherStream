The bridge had a real early-close bug: the busy path returned 429 without consuming the request body, allowing connection resets while clients were still uploading.
The handler now reads the declared body within the existing 4 KB limit before checking BUSY and explicitly sends Connection: close with close_connection set.
Added a split-body HTTP regression test verifying that 429 waits for the remaining upload, returns the busy JSON, and never invokes the CLI; documented the behavior in scripts/ai-bridge/README.md.
On Windows with Python 3.14.3, python -m unittest test_ai_bridge passed five consecutive runs (10 tests per run, 50 total).
The runs emitted non-fatal HTTPError cleanup ResourceWarnings; no failures or errors remain in these runs.
No live demo, port 8088, Docker, swarm processes, or real Claude CLI were used; live nginx verification was intentionally not performed.
