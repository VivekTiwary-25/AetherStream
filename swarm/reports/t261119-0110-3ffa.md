# t261119-0110-3ffa (T14 worker runtime)

I added the worker runtime in `engine/src/main/java/io/aetherstream/engine/worker/`. It has `WorkerMain` (register with a retry every 1 s, heartbeat loop, `/health` on 8090) and `Worker` (runs commands, applies the generation rules, builds WorkerStatus). `TaskRuntime` runs three threads joined by two queues of 1000. The source thread puts barriers in the queue with its own next-offset count for each partition. The operator thread runs `PartitionPipeline` and takes snapshots. The sink thread writes fenced batches (200 outputs or 200 ms or a barrier), then uploads the WorkerSnapshot, then acks. Kafka, Postgres and HTTP sit behind small interfaces (`RecordSource`/`KafkaRecordSource`, `ResultSink`/`PostgresResultSink`, `CoordinatorClient`/`HttpCoordinatorClient`).
Tests in `engine/src/test/java/io/aetherstream/engine/worker/` need no Docker. They cover: runtime outputs equal running `PartitionPipeline` directly, barrier ack offsets, restore giving the same results end to end, fencing (runtime stops, nothing written after), backpressure (both queues full, source blocked), and the generation / KILL / SET_SINK_DELAY rules.
`./gradlew build` passed locally on JDK 21 (9 worker tests, worker tests re-run 3 times with no flakes). CI has not run yet.
One contract issue: comparing generations across executions would ignore every new execution, because each one starts again at generation 1. So the worker compares generations only within the same executionId.
