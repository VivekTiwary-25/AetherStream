# t261119-1003-dca3 (T177, R08 #1 + #4 + restart policy)

1. Compare memory no longer grows with run length. The new `control-api/.../compare/BoundedReplay` streams the whole lineage one partition at a time: `KafkaRangeReader.stream` passes records to a callback, and `read` is now a thin wrapper around it. Operator state is still built exactly from the lineage root, including T93 restores (only the final stage's outputs count). Only results whose event-time end is inside a horizon of each partition's final maxTs are kept. The horizon is `aetherstream.compare.retention-ms`, default 1 h, and is never less than 3× the widest window plus its out-of-orderness. Engine rows are filtered the same way: SQL `window_end>?` / `event_time>?` on the smallest cutoff, then the key's own cutoff in the row mapper. So the result stays "N / N" with N > 0.
2. New `BoundedReplayTest`: about 96k synthetic records over 100 event-hours hold no more results at peak than a 10-hour run (a counted peak, not heap), and the horizon matches a full engine replay exactly, both single-stage and restored. `CompareServiceTest` and `CompareContractTest` were adapted to the streaming per-partition reader and the bounded result queries.
3. Added `CREATE INDEX IF NOT EXISTS` on `(execution_id, written_at)` for `window_results`, `alerts` and `dead_letters`, in `infra/db/schema.sql` (no semicolons in the comments) and in `OrgMigration`. Added `restart: unless-stopped` to kafka, postgres, minio, simulator, control-api and web.
4. Nothing was built or run locally (vivek-pc rule). ci-java, ci-integration and ci-e2e on this branch still need to pass, including e2e step 9.
5. Contract note: contract 04 "Compare with reference" says every reference row in `[cp0, C)` is compared. Results are now limited to the last horizon of event time, so the owner may want to add a line about this to the contract. Replay time still grows with run length (Kafka is re-read from the root), but memory does not.
