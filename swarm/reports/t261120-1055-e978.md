# t261120-1055-e978 — speeding / avg-speed-30s gave 0 live results

**avg-speed-30s root cause:** `PipelineEvaluator.tick` closed idle windows at `wallNow - 2s`, but `eventTime` is simulator time. The simulator anchors it as START_EPOCH_MS + (wall - SIM_ANCHOR_EPOCH_MS) * timeScale, which is days away from the wall clock (~7.8 days behind it in the live run). So every window was already "finalized" and every row was dropped by the never-reopen rule. Fix: idle closing now uses an event-time clock, estimated as the newest source eventTime plus wall time elapsed since that row arrived. When the two clocks match, behaviour is unchanged. Live, a 30 s window (3 s of wall time at timeScale 10) closes after a few seconds.
**speeding root cause:** the simulator caps speed at 50 km/h (street limits are 50 or 35, cruise is 0.85–1.0 of the limit, and the speed curve runs 0.65–1.0 of cruise), so `> 60` could never fire. The threshold is now 45 km/h in schemas/examples/speeding.json, examples.ts, the PipelinesPanel placeholder, panels.test.tsx and the Kafka IT boundary values. 7 of the first 40 real partition-2 rows are above 45 (peaks 45.8–49.7).
**Checks:** new `PipelineEvaluatorTest.emitsThirtySecondAveragesFromRealSimulatorRowsWhoseEventTimeIsFarFromWallTime` replays 40 real rows from partition-2-results.json with simulator-anchored event times. It asserts the first average arrives within 35 s (it arrives about 2.6 s after the first row), that the average is correct, that idle closing works, and that no row is dropped. It fails on the old code with 0 results. One existing test now delivers rows at their eventTime. Gradle glorious unit tests: 34/34 passed.
