# Performance check on a slow laptop profile (measure, then small safe wins)

Files: web/src/glorious/home/**, web/src/glorious/map/** (loading only), web/index.html (preload hints only), design/ui-glorious/PERF.md (new). Do NOT read or describe swarm/. Node: prepend %USERPROFILE%\tools\node if needed. Before finishing: in web/ npm run lint, npm test -- --maxWorkers=2, npm run build, npm run check:no-mock must pass. This PC has ~3 GB free RAM: one build at a time.

The expo laptop is low-RAM. Build for production, serve with npx vite preview, and use Playwright Chromium with CPU throttling (CDP Emulation.setCPUThrottlingRate 4) and 'Fast 3G'-like network off (local) to measure: time to first paint of Home (poster/video), JS bytes before Home is interactive, time from clicking Live World to the map's first 'idle' event, and JS heap after 2 minutes on Live World (backend may be absent; that is fine). Then apply ONLY small, safe wins if they help (e.g. preload the poster, video preload='metadata', prefetch the LiveWorld chunk after Home is idle, defer non-critical fonts) and measure again. Write PERF.md: before/after table + what changed. No visual or behaviour changes.
