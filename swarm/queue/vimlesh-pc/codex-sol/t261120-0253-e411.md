# Fix: MapLibre basemap does not render in the PRODUCTION build ("Worker failed to load")

Files: web/src/glorious/map/LiveWorld.tsx (worker setup only), web/vite.config.ts (only if needed), infra/docker/nginx.conf (MIME fix), tests/ui/glorious.spec.ts (add one assertion). Do NOT read or describe swarm/.
Node: if not on PATH prepend %USERPROFILE%\tools\node.

Boss findings on a production build (`npm run build`, dist served by nginx:1.29-alpine with infra/docker/nginx.conf): the Live World map shows only the cream background; trucks render; the page/console shows `Error: Worker failed to load. Check that the worker URL is correct.`
1. nginx serves `assets/maplibre-gl-worker-*.mjs` as `application/octet-stream` (nginx mime.types has no .mjs). Fix in infra/docker/nginx.conf inside the server block: `location ~* \.mjs$ { types { } default_type text/javascript; }` (keep the SPA fallback working; do not break other locations).
2. Even with the right MIME, MapLibre still fails: in the page, `new Worker(url, {type:'module'})` on that file LOADS fine, but `new Worker(url)` (classic) throws `SyntaxError: Unexpected token 'export'` (the file ends with `export{yT as default}`). So LiveWorld.tsx's `maplibregl.setWorkerUrl(mapWorkerUrl)` with `maplibre-gl/dist/maplibre-gl-worker.mjs?url` makes MapLibre (v6.19) start a CLASSIC worker on an ES-module file. Read node_modules/maplibre-gl (package.json exports, dist/ files, README/docs on setWorkerUrl / CSP build) and pick the supported setup for v6 with Vite: e.g. the classic CSP worker bundle (`maplibre-gl-csp-worker.js?url` with the matching CSP main build), or no setWorkerUrl at all if the default build inlines its worker, or whatever v6 documents. Must work fully offline (no CDN).
3. Verify in a REAL browser against a PRODUCTION build (not vite dev): build, then serve dist with `npx vite preview` AND with a quick static server that serves .mjs as application/octet-stream like stock nginx would (to prove the fix does not rely on MIME if you avoid .mjs), use Playwright (chromium) to open /live and assert: no console error containing "Worker failed", and the map canvas has rendered tiles (e.g. `map.loaded()` / a 'idle' event, or pixel check that the canvas is not a single flat colour). Screenshot to design/ui-glorious/proof/map-prod.png.
4. Add to tests/ui/glorious.spec.ts test 1: fail on any console error containing "Worker failed to load".
5. lint, `npm test -- --maxWorkers=2`, build, check:no-mock pass. Report the root cause and the chosen setup.
