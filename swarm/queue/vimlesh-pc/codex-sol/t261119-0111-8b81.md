# T18: control-api WebSocket `/ws` (live push to the UI)

Lane 3 (control-api). Implement the WebSocket part of contract 04 exactly (plain WebSocket, no STOMP). The control-api
core (CoordinatorClient, SimulatorClient, ResultRepository, ControlApiController) is on main: reuse those beans; do not
change their public methods (you may add new methods to ResultRepository in a NEW class instead, see Files).
Spring Boot 3.5.16, spring-boot-starter-websocket is already a dependency.

Files (create only these):
- control-api/src/main/java/io/aetherstream/api/ws/** (WebSocketConfig, LiveHub/broadcaster, pollers, message records)
- control-api/src/test/java/io/aetherstream/api/ws/**

Behaviour:
- Endpoint `/ws`, allowed origins `*`. Track sessions in a concurrent set; send with a per-session lock (or
  ConcurrentWebSocketSessionDecorator with a send-time limit 2 s and buffer 512 KB) so a slow browser never blocks others.
- On connect send `snapshot` (current execution, workers, summary, simulator state - each part null if its upstream is down).
- Scheduled (one ScheduledExecutorService, start only when at least one session is connected):
  `trucks` every 250 ms (simulator /state -> trucks + simTime), `workers` every 1 s (coordinator /coord/state),
  `flow` every 1 s (eventsPerSec = sum of worker recordsPerSec; byPartition = split by each worker's partitions evenly;
  rejectedPerSec / latePerSec from dead_letters count deltas), `windows` / `alerts` / `deadLetters` every 1 s with only NEW
  rows since the last poll (track the max `written_at` seen, plus keys at that instant to avoid duplicates),
  `execution` when the execution state, generation, restoredFromCheckpoint or lastCompletedCheckpoint changes, with the
  `event` field derived: STARTED / CHECKPOINT_COMPLETED / WORKER_DEAD (a worker disappeared or alive=false) / RECOVERING /
  RECOVERED / STOPPED.
- Every message: `{"type","ts","data"}`. Upstream failures are logged at most once per 30 s and never kill the scheduler.

Tests: a unit test of the execution-event derivation (state transitions -> event names); a unit test that the "new rows"
tracker never emits a row twice and never misses rows with equal timestamps; a Spring Boot test with a real embedded server
(random port) where a standard Java WebSocket client (java.net.http.WebSocket) connects and receives `snapshot` within 3 s
(mock the upstream clients and repository with @MockitoBean).

Acceptance check: `ci-java` workflow green on your branch.
