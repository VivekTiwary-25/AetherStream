# T162: Fix the flaky Gradle dependency resolution inside docker builds (CI reliability for the live demo)  [CI, hard]

Lane 7. About 1 in 4 runs of ci-e2e / ci-ui-e2e / ci-images fail in "Build and start stack" after ~49 s with:
"Could not resolve all artifacts for configuration 'classpath'. > Could not find org.springframework.boot:spring-boot-buildpack-platform:3.5.16
> Could not find org.springframework.boot:spring-boot-loader-tools:3.5.16 > Could not find org.apache.commons:commons-compress:1.27.1
> Could not find org.springframework:spring-core:6.2.19" (e.g. run on branch task/t261119-0824-eefd, workflow ci-ui-e2e).
Several images build Gradle in parallel inside docker (infra/docker/*.Dockerfile via infra/docker/with-proxy.sh ./gradlew ...).
The live expo demo includes a push going through GitHub Actions, so this must not flake. Find the cause and fix it, e.g.:
pluginManagement { repositories { gradlePluginPortal(); mavenCentral() } } in settings.gradle(.kts) so plugin transitive deps
resolve from Central too; Gradle retry settings (systemProp.org.gradle.internal.http.connectionTimeout/socketTimeout,
org.gradle.internal.repository.max.retries); a BuildKit cache mount for ~/.gradle (RUN --mount=type=cache,target=/root/.gradle);
or build all jars once in one stage and COPY them into each service image. Keep image contents and ports the same.
Prove it: rerun the image build at least 5 times on your branch (workflow_dispatch / re-run) with 0 failures; list the run URLs.

Files (edit only these): settings.gradle*, build.gradle* (root, repositories/plugin management only), gradle.properties,
infra/docker/*.Dockerfile, infra/docker/with-proxy.sh, docker-compose.yml (build sections only, e.g. cache settings).

Acceptance check: ci-images and ci-e2e green 5 times in a row on your branch (paste the run URLs).
