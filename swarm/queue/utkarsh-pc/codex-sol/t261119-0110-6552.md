# T13: Reference executor (single process) + Kafka range reader + comparison logic

Lane 2 (reference). The trusted, deterministic single-process executor used by "Compare with reference" and by CI tests.
It must reuse the shared semantics on main: `io.aetherstream.compiler.ops.PartitionPipeline` / `ListCollector` /
`EnvelopeValidator` (never re-implement operators) and `io.aetherstream.compiler.PipelineCompiler`.

Files (create only these):
- reference/src/main/java/io/aetherstream/reference/** (ReferenceExecutor, KafkaRangeReader, ReferenceResult, Comparator, ...)
- reference/src/test/java/io/aetherstream/reference/**

What to build (contract 02 section 4, contract 04 "Compare with reference"):
1. `ReferenceExecutor.run(ExecutionPlan plan, Map<Integer, List<RawRecord>> recordsByPartition)` -> `ReferenceResult`:
   one fresh PartitionPipeline per partition, records in offset order; collects window results per sink id, alerts per sink
   id, dead letters, plus for each partition the final `watermarks()` and the set of keys seen in that partition.
   `RawRecord(int partition, long offset, String value)`.
2. `KafkaRangeReader.read(String bootstrap, String topic, Map<Integer, Long> fromInclusive, Map<Integer, Long> toExclusive)`:
   KafkaConsumer with manual assign + seek, reads each partition exactly up to toExclusive-1 (handles empty ranges), 30 s
   timeout, returns Map<Integer, List<RawRecord>>.
3. `ResultComparator.compare(ReferenceResult ref, List<EngineWindowRow> engineRows, long checkpointId, ...)` ->
   `io.aetherstream.common.api.CompareResult` exactly as contract 04 steps 3-4: MISSING / DIFFERENT (eventCount differs or any
   value |diff| > 1e-6) / EXTRA (engine row for a key seen in partition p of the reference with window_end <= that window
   node's final watermark W_p, not produced by the reference). Map a sink id to its window node via the plan (the sink's
   input). Also compare alerts (MISSING/EXTRA by alertId). `engineRows` are plain records the caller loads from Postgres:
   `EngineWindowRow(String sinkId, String key, long windowStart, long windowEnd, Map<String, Double> values, long eventCount)`
   and `EngineAlertRow(String sinkId, String alertId)`. mismatches capped at 50; counts are full counts.
4. Tests (no Docker): build records with a small deterministic generator (like the simulator's shape: 8 trucks, positions
   every 2 s sim time, deliveries, a stuck truck, some late/duplicate/malformed); ReferenceExecutor output is deterministic
   across runs; comparator says match=true when engine rows = reference rows; reports MISSING when a row is removed,
   DIFFERENT when a value is changed by 0.1, EXTRA when an extra closed-window row is added, and does NOT flag an engine row
   for a window that is still open in the reference (window_end > W_p).
