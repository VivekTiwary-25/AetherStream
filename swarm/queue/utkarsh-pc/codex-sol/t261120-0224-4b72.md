# Diagnose (and if safe, fix) Docker Desktop on this PC

Files: design/ui-glorious/docker-utkarsh.md (new: your findings). Do NOT read or describe swarm/. No admin rights; never uninstall, reset to factory defaults, or delete Docker data/volumes/images.

You are on utkarsh-pc. Docker Desktop's processes run but `docker info` times out (tried 2x20 min). Find out why and fix it if a safe user-level action does it. Every command needs a timeout (Start-Process + WaitForExit, or `timeout`); nothing may wait for input.
1. Diagnose: `wsl --status`, `wsl -l -v` (is `docker-desktop` Running/Stopped/missing?), Docker Desktop version, last 200 lines of the newest logs in `%LOCALAPPDATA%\Docker\log\host\` and `%LOCALAPPDATA%\Docker\log\vm\` (summarise errors only, do not paste secrets), `Get-Process *docker*`, free RAM/disk, whether virtualization/WSL is enabled (`systeminfo` Hyper-V section or `Get-ComputerInfo -Property HyperV*`), whether the `com.docker.service` is required/stopped (just report).
2. Safe fix attempt (only if the diagnosis does not show something needing admin/BIOS): stop Docker Desktop (`Stop-Process -Name "Docker Desktop" -Force` and its `com.docker.backend` user processes), run `wsl --shutdown` (this only stops WSL distros on THIS PC), wait 10 s, start Docker Desktop again (`Start-Process "C:\Program Files\Docker\Docker\Docker Desktop.exe"`), poll `docker info` (20 s timeout each) every 15 s for up to 8 minutes.
3. If `docker info` works: run `docker run --rm hello-world` (timeout 120 s) and stop. Report SUCCESS.
4. If not: write the most likely cause and the exact human action (e.g. "accept the Docker Desktop license dialog", "enable virtualization in BIOS", "run as admin: Start-Service com.docker.service", "WSL update needed: wsl --update") in design/ui-glorious/docker-utkarsh.md and your report.
