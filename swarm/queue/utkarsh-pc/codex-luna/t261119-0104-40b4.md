# T12: UX and design-thinking documentation (docs/ux/)

Lane 9 (docs). The CDD syllabus covers UX, design thinking, usability and Figma. Write clear, honest, well-structured
Markdown docs for AetherStream's UI. Read handoff.md (sections 2, 4, 11, 15) and docs/contracts/04-control-api-rest-ws.md.

Product (for context): a game-like browser city where trucks drive between a depot and stops; trucks emit events into Kafka;
a distributed stream engine computes per-truck 1-minute average speed, deliveries per minute and "truck hasn't moved for
10 min" alerts; floating glass panels show the engine's results; a visual pipeline editor (Source, Filter, Map, Key-by,
Window, Rule, Sink) with Validate + Run; a chaos panel (late events, slow output = backpressure, kill worker = recovery from
checkpoint); a "Compare with reference" button; the footer shows the deployed git commit. Style: dark navy/charcoal,
restrained luminous accents, glass panels, clay-like primary buttons, bento layout, motion only for state changes.

Files (create only these):
- docs/ux/README.md (index + one-paragraph summary)
- docs/ux/personas.md (4 personas from handoff.md section 4: pipeline author, operator, org admin, evaluator/examiner -
  goals, frustrations, what they need from the UI, a quote each; mark them as proto-personas, not research findings)
- docs/ux/journeys.md (user journeys: build + validate + run a pipeline; watch live results; survive a worker failure;
  verify correctness with compare; ship a change through CI/CD and see the footer change. Stages, actions, thoughts,
  emotions, pain points, opportunities - as Markdown tables)
- docs/ux/design-thinking.md (empathise, define (problem statements, How-Might-We), ideate (alternatives considered:
  plain dashboards vs city metaphor, etc.), prototype (low-fi wireframes as ASCII sketches + Figma plan), test (a small
  usability test plan: 5 tasks, success criteria, SUS questionnaire))
- docs/ux/usability-decisions.md (each decision tied to a usability principle: Nielsen heuristics, Gestalt, Fitts, Hick,
  colour + text for states (accessibility, WCAG contrast 4.5:1), error messages from the compiler, motion only on change,
  reduced-motion support)
- docs/ux/design-system.md (tokens: colours with hex and roles, type scale, spacing, radius, elevation/glass recipe, clay
  button recipe, state colours running/backpressured/checkpointing/recovering/paused/failed, components list)
- docs/ux/figma-plan.md (frames, components, variants, prototype flows to build in Figma; checklist)

Write in plain, simple English. Do not invent research results or user quotes as if they were real; label assumptions.

Acceptance check: files exist with real content (each at least ~60 lines except README); `ci-java` still green
(docs-only change; it will be skipped or pass).
