# T31: Coordinator: rejoin of restarted workers (controlled rebalance) + Prometheus metrics endpoint

Lane 1 (engine). The coordinator on main (engine/src/main/java/io/aetherstream/engine/coordinator/**) assigns partitions
at start and on recovery only; a worker that registers later (e.g. the killed container restarted by docker) gets nothing
until the next failure. For the demo, a restarted worker must rejoin. Read contract 03 and the coordinator code first.

Files (edit/create only these):
- engine/src/main/java/io/aetherstream/engine/coordinator/**
- engine/src/test/java/io/aetherstream/engine/coordinator/**
Do NOT edit engine/.../worker/**, storage/**, db/** (other tasks), nor docs/contracts/.

1. Controlled rebalance (handoff.md section 8 "Scaling": pause at a checkpoint, change assignments, resume - describe it
   honestly as a controlled pause, not interruption-free): when the execution is RUNNING and the set of live workers has
   changed (a new worker registered and stayed alive for 5 s, or `POST /coord/executions/{id}/rebalance` is called), and the
   current assignment is uneven (max partitions per worker - min >= 2, or a live worker has none), then: wait for the next
   COMPLETED checkpoint N (trigger one immediately), then bump generation, CANCEL all, ASSIGN round-robin over live workers
   from checkpoint N (same path as recovery but audit action `execution.rebalanced` and the execution goes through state
   RECOVERING -> RUNNING with `restored_from_checkpoint = N`). Never rebalance while RECOVERING. At most one rebalance per 30 s.
   Env `AUTO_REBALANCE` (default true).
2. `GET /coord/metrics` in Prometheus text format (no new dependency, write the text by hand): aether_workers_alive,
   aether_execution_generation, aether_checkpoints_completed_total, aether_checkpoints_aborted_total,
   aether_last_checkpoint_duration_ms, aether_recoveries_total, aether_last_recovery_duration_ms,
   aether_worker_records_per_sec{worker="..."}, aether_worker_queue_size{worker="...",queue="source|sink"},
   aether_worker_backpressured{worker="..."}.
3. Tests (fake clock, in-memory): kill a worker -> recovery onto 2 workers; a new worker registers -> after 5 s and the next
   completed checkpoint, a rebalance gives 2/2/2 partitions with generation +1 and restoredFromCheckpoint = that checkpoint;
   no rebalance while RECOVERING; rate limit; metrics text contains every metric name.
