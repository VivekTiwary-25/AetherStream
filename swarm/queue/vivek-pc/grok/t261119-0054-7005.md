# T09: Contract-faithful mock server for UI development (DEV ONLY)

Lane 6 (web). A small Node server that speaks contract 04 (REST + WebSocket) and contract 01 truck shapes with synthetic
data, so the UI lanes can build before the real backend is ready. It must never be used by the deployed build.

Files (create only these):
- web/mock/package.json (its own tiny package: type module, dependency `ws` only, script `start`)
- web/mock/server.mjs
- web/mock/README.md (how to run; big warning: DEV ONLY, the UI shows a MOCK DATA badge)
- web/mock/smoke.mjs (a self-test script)
- .github/workflows/ci-mock.yml

What to build:
1. `node web/mock/server.mjs` listens on port 18080 (env PORT). Uses only `node:http` + `ws`.
2. Implements every REST endpoint in contract 04 with correct JSON shapes and plausible, internally consistent fake data:
   a moving truck fleet (8 trucks on a 2000x2000 grid with 200 m streets, depot at 1000,1000, 24 stops) using simple
   Manhattan movement, sim time running 10x, 1-minute windows produced every 6 real seconds per truck (avg speed, deliveries),
   a stuck truck-007 alert after ~10 sim-minutes, occasional rejected/late dead letters, 3 workers with queue sizes, checkpoint
   ids increasing every 10 s. `/api/pipelines/validate` does simple checks (has source, has sink, window has keyBy upstream)
   returning contract 02 error objects. `/api/compare` returns a matching result. `/api/version` returns `{"commit":"mock","builtAt":""}`.
3. Chaos works visibly: kill-worker marks a worker dead, execution goes RECOVERING with "restoredFromCheckpoint" = last
   checkpoint for ~4 s then RUNNING with generation+1; slow-sink fills queues to capacity (backpressured true) until delay 0;
   late-events adds LATE dead letters; POST /api/simulator/trucks adds a truck.
4. WebSocket on `/ws` sending every message type in contract 04 at the stated rates, `snapshot` first on connect.
5. Every JSON body carries no extra "mock" fields (shapes must match the contract), but every HTTP response has header `X-Mock: 1`.
6. web/mock/smoke.mjs: starts the server on a random port, calls every REST endpoint and checks status + required keys,
   opens the WebSocket and checks it receives snapshot, trucks, workers within 3 s; exits non-zero on failure.
7. .github/workflows/ci-mock.yml: on push to main and task/**, pull_request: Node 22, `cd web/mock && npm install && node smoke.mjs`.

Acceptance check: `ci-mock` workflow green on your branch.
