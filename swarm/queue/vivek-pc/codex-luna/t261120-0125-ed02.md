## Track D shared contract (D1 backend, D2 frontend and D3 AI bridge are built in parallel against this)
Pipeline JSON (schema file: schemas/glorious-pipeline.schema.json, owned by D1):
```json
{"name":"Speeding alert","nodes":[
  {"id":"n1","type":"filter","params":{"field":"speedKmh","op":">","value":60}},
  {"id":"n2","type":"thresholdAlert","params":{"field":"speedKmh","op":">","value":60,"message":"Truck over 60 km/h"}},
  {"id":"n3","type":"output","params":{"name":"Speeding trucks"}}],
 "edges":[{"from":"n1","to":"n2"},{"from":"n2","to":"n3"}]}
```
- Exactly five node types: `filter {field, op, value}`, `pickFields {fields: string[]}`, `windowAverage {field, windowSec, groupBy?}`, `thresholdAlert {field, op, value, message}`, `output {name}`. Display names: Filter, Pick Field, Window Average, Threshold Alert, Output.
- op ∈ `>`, `>=`, `<`, `<=`, `==`, `!=`. Graph: acyclic, every path ends in an `output`, at least one output, each non-first node has exactly one input, max 12 nodes. The implicit source is the live truck position stream (no source node).
- Fields (the real truck position fields, RECON.md i): `truckId` (string), `speedKmh` (number), `heading` (number), `x` (number), `y` (number), `routeId` (string), `status` (string: DRIVING/UNLOADING/IDLE/STOPPED), `partition` (number 0-5, the REAL Kafka partition), `eventTime` (number, epoch ms). Numeric ops only on numeric fields; `==`/`!=` allowed on strings. groupBy ∈ {truckId, routeId, status, partition}.
REST (control-api, same origin under /api, D1 implements):
- `GET  /api/glorious/pipelines/fields` → `{fields:[{name,type,description}], nodeTypes:[...]}`
- `POST /api/glorious/pipelines/validate` body = pipeline → `{valid:boolean, errors:[{nodeId?:string, message:string}]}`
- `POST /api/glorious/pipelines/runs` body = pipeline → `201 {runId}` or `400 {valid:false, errors}`; starting a run stops the previous run (one run at a time).
- `GET  /api/glorious/pipelines/runs/{runId}/results?after=<seq>` → `{runId, state:"RUNNING"|"STOPPED"|"FAILED", error?:string, startedAt, eventsIn:number, results:[{seq, ts, output, kind:"row"|"alert"|"average", data:{...}}]}` (keep last 500 results)
- `POST /api/glorious/pipelines/runs/{runId}/stop` → `{state:"STOPPED"}`
AI (host-side bridge, D3 implements; reached by the browser through nginx at `/api/glorious/ai/`):
- `POST /api/glorious/ai/generate` body `{prompt:string}` → `200 {pipeline, source:"ai"|"example", note?:string, model?:string, ms:number}`; `429 {error:"busy"}` if another request is running. source "example" means fallback: note = "Showing a saved example: AI was unavailable".
- `GET /api/glorious/ai/health` → `{ok, model, configDir?:boolean}`


The control-api runs in Docker and cannot use the host's Claude login, so Ask AI is a tiny HOST process that nginx proxies to (`/api/glorious/ai/` → `http://host.docker.internal:18090/`).

## Build scripts/ai-bridge/ai_bridge.py (Python 3.10+, standard library ONLY)
- `http.server` ThreadingHTTPServer on 127.0.0.1 and the docker gateway (bind `0.0.0.0` only if env AI_BIND says so; default `0.0.0.0` is needed for host.docker.internal, so document the Windows firewall note), port env AI_PORT default 18090. Routes (paths WITHOUT the /api/glorious/ai prefix, nginx strips it): `POST /generate`, `GET /health`.
- One request at a time (non-blocking lock → 429 `{error:"busy"}`). Request body ≤ 4 KB, prompt ≤ 500 chars.
- Spawn Claude Code headless with an ARGUMENT LIST (subprocess, shell=False), the user text via STDIN, never interpolated into a shell string:
  `[AI_CMD or "claude", "-p", "--model", AI_MODEL or "claude-haiku-5-5", "--output-format", "json", "--tools", "", "--strict-mcp-config", "--no-session-persistence", "--disable-slash-commands", "--system-prompt", SYSTEM_PROMPT]`, env: copy of os.environ plus CLAUDE_CONFIG_DIR if set. Timeout 60 s (kill the process tree on timeout). Do NOT use --bare (it can skip the subscription OAuth login). Parse the CLI JSON (`result` field), extract the pipeline JSON object from it (strip ``` fences).
- SYSTEM_PROMPT: built from the schema file + the field list + the 3 examples (from schemas/examples/ if present); instruct: output ONE JSON object only, the five node types only, the listed fields only, short name.
- Validate the result by calling the control-api validator: `POST {AI_VALIDATE_URL default http://localhost:8088/api/glorious/pipelines/validate}`; if that endpoint is unreachable, fall back to a local structural check (types, params, edges acyclic) and say `validatedBy:"local"`. Invalid → retry ONCE with the error list appended to the prompt. Still invalid / CLI error / timeout → fall back to the closest saved example (simple keyword overlap between the prompt and example prompts) with `source:"example"` and `note:"Showing a saved example: AI was unavailable"` (and log the real reason to stderr).
- Response per contract, plus `validatedBy`. CORS not needed (same origin via nginx). Log one line per request (time, ms, source, valid) — never log secrets.
- start.ps1 / start.sh: start the bridge in the background with sensible defaults, write a pid file and log under scripts/ai-bridge/.run/ (gitignored). start.ps1 should default CLAUDE_CONFIG_DIR to `$env:USERPROFILE\.swarm\profiles\vachana-claude\claude` IF that folder exists (so Vivek's main Opus is not used), else leave it unset.
- README.md (20 lines): env vars AI_CMD, AI_MODEL, CLAUDE_CONFIG_DIR, AI_PORT, AI_VALIDATE_URL; how to start/stop; firewall note.
- test_ai_bridge.py (unittest, stdlib): use a FAKE AI_CMD (a small python script that prints a canned CLI JSON) to test: valid path, invalid→retry→fallback, timeout→fallback, busy→429, prompt via stdin (assert the prompt never appears in argv).
