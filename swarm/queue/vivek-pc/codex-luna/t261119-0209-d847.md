# T52: Scenario panel (presenter controls for the city)

Lane 6 (web/app). A compact glass panel with 4 scenario buttons that drive the simulator via the control-api:
`GET /api/scenarios` (list: name, label, description) and `POST /api/simulator/scenario {"name": "...", "truckId"?}`.
The current scenario comes from `GET /api/simulator/state` (field `scenario`) or the WebSocket `snapshot`.

Files (create only these):
- web/src/app/scenarios/** (ScenarioPanel.tsx, scenariosApi.ts with fetch helpers and local types, index.ts exporting `ScenarioPanel`)
- web/src/app/scenarios/__tests__/**
Do NOT edit any other file (an integration task mounts the panel).

UI: four ClayButtons (Rush hour, Breakdown (with a small truck picker defaulting to truck-005), Surge (+6 trucks), Reset),
each with a one-line description; the active scenario glows with a text label "Active: Rush hour"; disabled while a request is
in flight; plain-English inline errors (e.g. "Simulator is not reachable"). If /api/scenarios 404s, fall back to the built-in
list of the same 4 scenarios. Use GlassPanel/ClayButton from web/src/app/ui (import only). Reduced-motion aware.

Tests (Vitest, mock fetch): clicking Rush hour posts {"name":"rush-hour"}; breakdown posts the chosen truckId; 404 fallback
list renders; error message on 502.

Acceptance check: `ci-web` green on your branch.
