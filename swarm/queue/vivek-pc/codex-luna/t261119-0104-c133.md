# T11: API client + live glass panels (bento): speed windows, deliveries/min, alerts, dead letters, workers

Lane 6 (web/app). Build the floating glassmorphic panels that show results the ENGINE computed, fed by the REST + WebSocket
API in contract 04.

Files (create/edit only these):
- web/src/api/types.ts (TypeScript types mirroring contract 04 + contract 03 section 7 exactly; same field names)
- web/src/api/client.ts (typed fetch helpers for every REST endpoint in contract 04; errors -> thrown `ApiError` with code/message)
- web/src/api/ws.ts (`useAetherSocket()` React hook: one shared WebSocket to `/ws` (same origin, ws/wss by protocol),
  reconnect with backoff 1 s -> 10 s, typed message dispatch, exposes connection status)
- web/src/app/state/** (a small store, e.g. React context + useReducer or zustand if you add it, holding latest execution,
  workers, windows (keep the last 200), alerts, dead letters, summary, flow)
- web/src/app/panels/** (SpeedWindowsPanel, DeliveriesPanel, AlertsPanel, DeadLettersPanel, WorkersPanel, ExecutionBanner)
- web/src/app/shell/AppShell.tsx (place the panels into the bento slots; do not touch the city line)
- web/src/app/__tests__/** (Vitest + Testing Library)
- web/package.json + web/package-lock.json only if you add a dependency (keep it minimal)

Do NOT edit web/src/city/** (another task is building the city at the same time).

Panels (use the existing GlassPanel / StatusPill / ClayButton and tokens.css; bento layout, readable contrast, no clutter):
1. SpeedWindowsPanel: per truck, the latest 1-minute window average speed (sink `speedSink`), a tiny sparkline of the last
   10 windows per truck (inline SVG), sorted by truck id; window time shown as HH:mm sim time.
2. DeliveriesPanel: deliveries per minute (sum of `deliveries` over sink `delSink` per window), big number for the newest
   window + bar sparkline of the last 15 windows.
3. AlertsPanel: newest first, e.g. "truck-007 has not moved for 10 min", with sim time; a new alert animates in once.
4. DeadLettersPanel: two tabs or counters REJECTED / LATE with the latest reasons.
5. WorkersPanel: one row per worker: id, partitions, recordsPerSec, source/sink queue bars (bounded queue, capacity 1000),
   state pill: healthy / backpressured (amber, when `backpressured`) / dead (red, `alive=false`).
6. ExecutionBanner (top centre): execution state with text + colour: RUNNING, "Checkpoint #N" flash on CHECKPOINT_COMPLETED,
   "Worker w-… lost" then "Recovering from checkpoint #N" (RECOVERING), then "Recovered in X s" (RECOVERED), STOPPED.
   Also a "Start demo pipeline" ClayButton when there is no execution: GET /api/pipelines/demo, POST /api/pipelines,
   POST /api/pipelines/{id}/executions with a random idempotencyKey.
7. Motion only on state changes (new values, alerts); respect prefers-reduced-motion.

Tests: types compile against sample JSON fixtures copied from contract 04; reducer handles each WS message type;
WorkersPanel shows "backpressured" and "dead" labels; ExecutionBanner shows "Recovering from checkpoint #12".
