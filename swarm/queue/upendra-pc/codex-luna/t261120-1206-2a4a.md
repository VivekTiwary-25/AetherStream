# Live World: fleet poll must never stop for good (timeout + keep polling)

Files: web/src/glorious/map/useLiveFleet.ts, web/src/glorious/map/useLiveFleet.test.tsx.
Rules: Do not read, explain or modify swarm/ code (writing your own task report file is the one exception). Never stop, restart or change the swarm. Every command needs a timeout; nothing may wait for input. Never touch port 8088 or the live demo on vivek-pc, never start Docker. No mock, fake or placeholder data. ~20 min.

Finding 4 in design/ui-glorious/proof/review/REVIEW-1145.md: fetch('/api/simulator/state') in useLiveFleet.ts has no timeout and the next poll is only scheduled after it settles, so one hung request freezes Live World. Add a per-request timeout (AbortSignal.any([controller.signal, AbortSignal.timeout(4000)]) with a fallback for environments without AbortSignal.any), treat a timeout like any other failed poll (existing stale/backoff behaviour), and always schedule the next poll. Add a fake-timer vitest: a never-resolving fetch is aborted after ~4 s, the hook marks data stale, and the next poll runs and recovers when fetch works again. Run `npx vitest run src/glorious/map` (NODE_OPTIONS=--no-experimental-webstorage on Node 26) + typecheck. End with a short report.
