# PipelineEvaluator: a consumer stall must not close windows early or drop the backlog

Files: control-api/src/main/java/io/aetherstream/api/glorious/PipelineEvaluator.java (+ PipelineRuns.java only if needed), control-api/src/test/java/**/glorious/PipelineEvaluatorTest.java. Start from the LATEST origin/ui-glorious (it includes the edge-case tests task if merged).

Confirmed bug (design/ui-glorious/proof/review/REVIEW-1145.md, finding 3): the idle clock eventNow = newest source eventTime + wall time since that row moves at 1x while simulator event time moves at 10x. During a stall (Kafka hiccup, rebalance, GC) of >= 2 s, tick() keeps advancing finalizedThrough, emits partial windows and then DROPS the backlog rows that arrive after the stall. Fix with the smallest safe change, e.g. only let the idle clock close a window when the source has been idle (no rows) for longer than that window's length plus a margin, OR cap the idle advance so it never passes the newest row's eventTime by more than the window length; keep steady-state behaviour (first 30 s average within ~35 s of Run) and the 'events stopped -> last window still closes' behaviour. Add tests: 10 s stall then backlog -> no rows dropped, windows complete; steady flow unchanged; simulator paused -> last window closes. Run the glorious unit tests via Gradle (no Kafka ITs). End with a short report.
