# T78: Chaos soak test: repeated worker kills + slow sink + late events for 15 minutes, results must still match

Lane 7/8 (infra/tests). For demo confidence: prove the system survives many failures in a row without leaking state or
drifting from the reference. The stack runs with `docker compose up -d --build` (root docker-compose.yml). The control-api
endpoints are in contract 04 (+ /api/compare, /api/chaos/*, /api/workers, /api/executions/current).
infra/scripts/demo-e2e.sh shows the request helpers style (do not edit it; another task owns it).

Files (create only these):
- infra/scripts/soak.sh (bash, set -euo pipefail, curl + jq; env API default http://localhost:18080, DURATION_S default 900)
- .github/workflows/ci-soak.yml (workflow_dispatch + schedule nightly + push to task/** for your own verification; NOT on
  push to main)

soak.sh: start the demo pipeline; then loop until DURATION_S: every 90 s kill a random alive worker
(`docker compose kill worker-N`, it restarts), every 120 s toggle slow-sink 200 ms for 30 s, every 60 s send 10 late
events; after each kill wait for RUNNING with a higher generation (fail if > 30 s) and record recovery time; every 3 minutes
POST /api/compare and require match=true; at the end print a summary table (kills, recoveries with min/avg/max time,
compares all matched, checkpoints completed, rejected/late counts, container restarts from `docker inspect`, memory per
container from `docker stats --no-stream`). Exit non-zero on any failure. Write the summary also to soak-summary.md.

ci-soak.yml: ubuntu-latest, timeout 40 min, compose up --build --wait, run soak.sh, upload soak-summary.md and compose logs
as artifacts, add the summary to $GITHUB_STEP_SUMMARY, always down -v. Use current action majors (checkout@v7,
upload-artifact@v7). Shellcheck the script in a first step.

Acceptance check: `ci-soak` green on your branch with the summary in the step summary (paste it in your result).
